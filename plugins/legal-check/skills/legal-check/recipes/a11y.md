# Recipe: accessibility basics (ADA / WCAG 2.1 AA)

Goal: fix the common, mechanical WCAG failures that show up in demand letters. This is
not a full audit.

## Done when
- Every meaningful image has descriptive alt text; decorative ones `alt=""`. Write alt
  from what the image shows in context (file name, surrounding text); if you can't tell,
  use a `TODO(legal-check): describe image` alt and list it.
- Every form field has a visible `<label>` (or `aria-label` when a visible label truly
  doesn't fit); placeholders are not labels.
- Clickable `div`/`span` become `<button type="button">` (or links `<a href>`), so they
  work with keyboard; icon-only buttons get `aria-label`.
- Focus is visible: remove `outline: none` / `outline-none` without replacement; add
  `:focus-visible { outline: 3px solid <accent>; outline-offset: 2px; }`.
- Zoom isn't blocked: remove `user-scalable=no` and `maximum-scale=1`.
- `<html lang="…">` is set.
- Obvious low-contrast text colors in CSS (e.g. light grey on white, dark grey on black)
  are darkened/lightened to at least 4.5:1 for body text. State that contrast was only
  spot-checked.

## Stack notes
- React/JSX/TSX: `alt`, `htmlFor`, `aria-label`; `className` stays.
- Vue/Svelte/Astro/HTML/Jinja/ERB: plain `for`, `alt`, `aria-label`.
- Expo / React Native: `accessibilityLabel` + `accessibilityRole="button"` on
  Touchable/Pressable (especially icon-only), `accessibilityLabel` on TextInput (don't rely
  on placeholder), `accessible` + `accessibilityLabel` on meaningful Images.
