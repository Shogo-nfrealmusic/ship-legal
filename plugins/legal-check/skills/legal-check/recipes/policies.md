# Recipe: privacy policy and terms pages

Goal: pages exist, are linked from every page (footer), and describe what the code
actually does. They are drafts until a lawyer reviews them.

1. Build the facts list from the scan and the code, not from imagination:
   what is collected at sign-up, analytics / session replay tools, email provider,
   payment provider, file storage, cookies used, where data is hosted if known.
2. Privacy page (`/privacy`): who you are (placeholder), what you collect, why,
   which third parties receive it (name each tool found), session recording + masking
   + how to decline (if replay exists), cookies, children ("not directed to children
   under 13"), how to contact / delete data, effective date placeholder.
3. Terms page (`/terms`): who can use it (13+ if an age screen exists), user content
   rules and license, subscription/renewal/cancel summary if there is billing,
   DMCA link if uploads exist, disclaimers and limitation of liability as placeholders,
   governing law placeholder.
4. Mark every unknown with `TODO(legal-check): ...` in the source. Add a code comment
   at the top of each file: "DRAFT generated by /legal-check. Have a lawyer review
   before relying on it." Never state facts you don't know (company name, address,
   data retention periods, jurisdictions).
5. Add footer links to /privacy and /terms (and /dmca if created) in the root layout
   or shared footer component so they appear on every page.

Reason to state in the report: California's CalOPPA requires a commercial website that
collects personally identifiable information from California residents to post a
privacy policy conspicuously.
